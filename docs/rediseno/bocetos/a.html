Its limits

n = 10, from a single run, and the model varies from one run to the next.

The one session without slurp had a prompt that named both symbols to change and the component they live in. The agent grepped for them: with the names given, the task was finding them, not working out where the code lives, which is what slurp_query is for.

The refresh was barely exercised. Agents call slurp when they start, before editing: 15 of the 16 calls found the graph current and one refreshed it, in 325 ms.

Only 4 of the 26 files edited had a slurp_impact or slurp_explain first.
