§ 07How it works

Measured with agents

Before the v1.3.0 release, ten claude -p sessions (Claude Code 2.1.331, Claude Opus 5.5) each did one task in a fresh clone set up with slurp init --yes — five on slurp itself, five on PrismaStats. No prompt mentioned slurp. Against a criterion fixed before measuring (8 of 10 sessions needed):

9 of 10

sessions called slurp on their own, all 9 before their first edit

0

approvals: no slurp tool was denied

10 of 10

tasks completed: the project's checks pass and the diff does what the task asked

Its limits

1n = 10, from a single run, and the model varies from one run to the next.

2The one session without slurp had a prompt that named both symbols to change and the component they live in. The agent grepped for them: with the names given, the task was finding them, not working out where the code lives, which is what slurp_query is for.

3The refresh was barely exercised. Agents call slurp when they start, before editing: 15 of the 16 calls found the graph current and one refreshed it, in 325 ms.

4Only 4 of the 26 files edited had a slurp_impact or slurp_explain first.
